# Documentation Compilation Scripts

This directory contains scripts for compiling Chainguard documentation into a single bundle for AI assistants.

## Files

- `compile_docs.py` - Main compilation script
- `quick-start-guide.md` - Template for the Quick Start Guide
- `requirements.txt` - Python dependencies

## Quick Start Guide Template

The `quick-start-guide.md` file contains the content that appears at the beginning of every compiled documentation bundle. This approach provides several benefits:

### Benefits

1. **Easy Updates**: Edit the markdown file without touching Python code
2. **Version Control**: Track changes to the guide separately
3. **Markdown Preview**: See how it looks in any markdown editor
4. **Reusability**: Can be included in other documentation
5. **Collaboration**: Non-developers can edit the guide

### Editing the Guide

To update the Quick Start Guide:

1. Edit `scripts/quick-start-guide.md`
2. Run the compilation: `python3 scripts/compile_docs.py`
3. The updated guide will appear in the next compilation

### Structure

The guide should include:

- Usage tips for different AI tools
- Example prompts for common tasks
- Search strategies
- Document structure overview

## Running the Compilation

```bash
# From the edu directory
python3 scripts/compile_docs.py
```

The compile workflow creates the compressed `.tar.gz`, `.gz`, and `.zip` bundles after compilation.

## Automation

The compilation runs automatically via GitHub Actions when:

- Changes are pushed to the edu repository
- Other repositories trigger updates
- Daily at 2 AM UTC
- Manual workflow dispatch

The Quick Start Guide will always be included at the top of the compiled documentation.

## Built-in roles capabilities table

`capabilities-table/generate.py` builds the capabilities table on the
[built-in roles and capabilities reference](../content/platform/administration/iam-organizations/roles-role-bindings/capabilities-reference.md)
from the deployed IAM roles. Don't edit the table by hand. It sits between
two `generated by scripts/capabilities-table/generate.py` comment markers,
and the script overwrites everything between them.

To refresh the table:

1. Log in with `chainctl auth login`, then save the deployed roles:

   ```bash
   chainctl iam roles list -o json > roles.json
   ```

2. Run the generator:

   ```bash
   python3 scripts/capabilities-table/generate.py roles.json
   ```

3. If the script reports errors, edit `capabilities-table/purposes.toml`
   and run it again. The script stops when a documented role grants a
   resource that has no Purpose text, when a documented role no longer
   exists, or when `purposes.toml` names a resource that no documented
   role grants.

4. Review the diff. A new role isn't documented until you add it to the
   `roles` list in `purposes.toml`. The prose sections of the page, such
   as the role summary and the comparison table, aren't generated, so
   update them by hand.

To see whether the table is current without changing it, add `--check`.
The script exits with status 1 if the page is out of date. Python 3.11 or
later is required, for `tomllib`. No CI job runs this script.

## Checks and Workspaces YAML examples

`checks-examples/validate.py` checks the `.chainguard/` YAML examples on the
Chainguard Checks and Chainguard Workspaces pages with
`chainctl checks validate`. That command runs offline and needs no
Chainguard account, only `chainctl` on your `PATH`.

Run it from the repository root before you review or merge a change to
those pages:

```bash
python3 scripts/checks-examples/validate.py
```

The script prints the `chainctl` version it used, then a PASS, FAIL, or
SKIPPED line per example, with the validator's message under each failure.
It exits with status 1 if any example fails.

Each example is validated alone, in a scratch repository of its own.
`checks-examples/examples.toml` lists the exceptions: examples that only
validate together with another file, and excerpts that the script skips.
Every entry gives its reason. If an example that the file doesn't mention
fails, the script says so. Fix the example, or add an entry for it, then
run the script again. If an entry no longer matches an example on its
page, the script stops with status 2 and names the entry.

The script reads `.chainguard/` titled blocks and untitled `yaml` blocks.
It writes an untitled block as a `.chainguard/ci.yaml` fragment, adding
`version: 1` and `environment: {}` if they're missing. It skips the
`.chainguard/develop.yaml` examples, because `chainctl checks validate`
doesn't read that file.

The configuration schema changes with `chainctl` releases, so a failure
can mean that the docs are out of date or that your `chainctl` is. No CI
job runs this script. Python 3.11 or later is required, for `tomllib`. To
run the script's tests, which don't need `chainctl`:

```bash
python3 -m unittest discover -s scripts/checks-examples -v
```
